# Развёртывание на хостинге (панель с `main.py`)

Панели вроде Pterodactyl / Pelican запускают бота как `python main.py` и ставят
зависимости через `pip`. Проект использует `uv` для разработки, но для панели есть
адаптер — `main.py` в корне репозитория.

## Что отвечать в панели

| Поле | Ответ |
|---|---|
| **Bot Main File** | `main.py` |
| **Среда выполнения** | `Python 3.13` |
| **User Uploaded Files** | включено, **если** заливаешь файлы сам через SFTP |
| **Git Repository Address** | URL репозитория, если будешь деплоить через git (иначе пусто) |
| **Git Branch** | `master` (или твоя ветка) |
| **Additional Python Packages** | `-r requirements.txt` |

Если заливаешь через git — `User Uploaded Files` можно оставить включённым, он не
мешает.

## Что где хранится

Это главное разделение: **данные на сервере, конфигурация в git**.

| Что | Где | Почему |
|---|---|---|
| Сообщения, рапорты, реакции, вердикты, недельные результаты | БД на сервере | меняются каждую минуту, живут только там |
| Формы рапортов | `forms/*.yaml` | конфигурация, ревьюится в git |
| Лестницы рангов | `forms/ladders/*.yaml` | конфигурация |
| **Список обслуживаемых каналов** | `forms/channels.yaml` | конфигурация |
| Токен, настройки | `.env` на сервере | секрет, в git не попадает |

Настроил канал локально → закоммитил `forms/channels.yaml` → задеплоил. Сервер при
старте приведёт базу в соответствие с файлом. Сливать базы не нужно: рантайм-данные
существуют только на сервере.

## channels.yaml живёт в /data, а не в репозитории

Раньше файл лежал в `forms/` и терял правки при каждом передеплое: панель заменяет
весь код, оставляя только `/data`. Теперь живой файл — **в папке данных**:

```
/data/channels.yaml          # живой файл, правится на сервере
forms/channels.yaml          # только образец, копируется один раз
```

- первый старт копирует образец в `/data`, если файла там ещё нет
- повторный передеплой **не перезаписывает** то, что вы отредактировали
- бот проверяет изменение файла раз в несколько секунд и применяет его **без
  перезапуска**
- битая правка (опечатка в YAML) пишется в лог и игнорируется: продолжает работать
  предыдущая конфигурация, а не «ничего не привязано»

Путь можно переопределить: `DSBOT_CHANNELS_FILE=/data/my-channels.yaml`.

```yaml
channels:
  - guild: 1209516013779943544      # сервер, в котором лежит канал
    channel: 1573045809774067812    # сам канал
    form: training_report           # форма из forms/
    rank_guild: 1274460259661910149 # чей сервер хранит РОЛИ (опционально)
    review_ladder: review           # кто одобряет (forms/ladders/review.yaml)
    quota_ladder: quota             # кто сдаёт и сколько (forms/ladders/quota.yaml)
    locale: ru
    enabled: true                   # false = пауза, история сохраняется
```

`review_ladder` и `quota_ladder` задаются **на канал**, поэтому два канала могут
упорядочивать одних людей по-разному, а канал может иметь только проверку или только
нормы. Лестницы берутся из `forms/ladders/<key>.yaml` и применяются сами.

```powershell
python main.py channels-check    # проверить живой файл И названные в нём лестницы
python main.py channels-apply    # применить сейчас, не дожидаясь наблюдателя
python main.py channels          # что реально привязано
```

Свойства, на которые можно рассчитывать:

- **идемпотентно** — повторный `apply` ничего не меняет, лестницу не пересоздаёт
- **ростер не теряется** — неизменившаяся лестница не пересобирается, поэтому
  скрапленный список людей переживает передеплой
- **пауза уважается** — `enabled: false` не включает канал обратно при рестарте
- **ничего не удаляется** — убрал канал из файла, привязка и история остались
- **старт читает файл всегда** — на панели без консоли достаточно передеплоить

Если файла нет совсем, бот запустится и скажет `no_channel_bindings` с подсказкой,
а не упадёт.

### Почему это важно на панели

Панель сохраняет только `/data`. Всё остальное при передеплое заменяется содержимым
git, поэтому любая настройка, сделанная на сервере руками, будет потеряна или
продублирована. Поэтому связи канал → форма → лестницы живут ТОЛЬКО в
`forms/channels.yaml` и восстанавливаются при каждом старте.
`ladder-apply` для обычной работы не нужен: он лишь применяет лестницу немедленно,
не дожидаясь рестарта.


Без них бот не запустится:

```
main.py
requirements.txt
pyproject.toml
src/dsbot/…            весь код
forms/training.yaml    форма рапорта
forms/ladders/         лестницы рангов (когда настроишь)
.env                   токен (создать вручную, в git его нет)
```

`var/` создастся сам — там SQLite.

## Создать `.env` на сервере

Файл в `.gitignore`, поэтому его никогда не будет в репозитории. Содержимое:

```dotenv
DSBOT_DISCORD_TOKEN=твой_токен
DSBOT_LOG_LEVEL=INFO
DSBOT_LOG_FORMAT=console
DSBOT_DEFAULT_TIMEZONE=Europe/Moscow
DSBOT_DEFAULT_LOCALE=ru
DSBOT_CONTACT_USER_ID=263344369451401227
DSBOT_REPORT_GROUP_WINDOW_SECONDS=120

# ОБЯЗАТЕЛЬНО для подсчёта: без этого интента Discord не отдаёт список участников,
# и люди без рапортов пропадут из таблицы вместо того, чтобы показать 0.
# Нужно также включить SERVER MEMBERS INTENT в developer portal.
DSBOT_ENABLE_MEMBERS_INTENT=true
```

`DSBOT_AUTO_BIND_CHANNELS` больше не нужен: каналы берутся из `forms/channels.yaml`,
который лежит в git и применяется при каждом старте.

Путь к БД **относительный** (`./var`), поэтому рабочий каталог процесса должен быть
корнем проекта. Панель так и делает.

## Первый запуск

Панель сама выполнит `pip install -r requirements.txt` и запустит `main.py`.
Таблицы создаются автоматически при старте — `init-db` не нужен.

Если панель даёт консоль, проверь:

```bash
python main.py doctor
```

Покажет, видит ли бот токен, серверы и каналы.

## Привязка каналов на сервере

Ничего делать не нужно: каналы описаны в `forms/channels.yaml` и применяются при
старте. Проверить, что получилось, можно из консоли панели:

```bash
python main.py channels
python main.py channels-check
```

Старые команды `form-apply` и `bind` по-прежнему существуют для ручной отладки, но
для деплоя они не нужны и на панели бесполезны: при следующем передеплое всё равно
победит файл.

## Перезапуск и остановка

Панель обычно сама убивает процесс по кнопке. Внутри консоли:

```bash
python main.py status
python main.py stop
```

`stop` работает и на Linux: он читает pid-файл и дополнительно ищет процессы
`dsbot run` через `ps`, потому что `uv run` может оставить ребёнка живым.

## Обновление кода

- **через git:** панель перетянет ветку при переустановке/рестарте
- **через файлы:** замени `src/` и перезапусти

Зависимости меняются редко; если менялись — переустанови (`pip install -r requirements.txt`).

**После `git pull` на сервере достаточно перезапуска.** Старт сам применяет
`forms/channels.yaml` к базе: новый канал из файла появится, изменённая форма
обновится, изменённая лестница пересоберётся, пауза из файла соблюдётся. Вручную
ничего запускать не нужно.

Список людей, который бот скрапит для подсчёта (`roster-refresh`), хранится в базе,
то есть в `/data`, и передеплой его не трогает — пока лестница не изменилась.
Изменил состав ролей в лестнице — после рестарта выполни `roster-refresh`.


## Где хранится база (важно)

Панель сохраняет при перезапуске **только одну папку** — обычно `/data`. Если база
лежит вне неё, каждый редеплой стирает все рапорты, вердикты и недельные отчёты.

Бот определяет папку сам, в таком порядке:

1. `DSBOT_DATA_DIR` (если задан в `.env`)
2. `DATA_DIR` (переменная панели)
3. существующая папка `/data` или `/app/data`
4. `./var` — для локальной разработки

Проверить, что выбралось:

```bash
python main.py status
```

```
instance: dsbot
database: sqlite+aiosqlite:////data/dsbot.db
state dir: /data
```

Если `state dir` указывает не на постоянную папку — задай её явно:

```dotenv
DSBOT_DATA_DIR=/data
```

Внутри лежат: `dsbot.db` (+ `-wal`, `-shm`), `dsbot.lock`, `dsbot.pid`.

**Не задавай `DSBOT_DATABASE_URL` вручную**, если не уверен: явный URL отменяет
автоопределение и может увести базу из постоянной папки.

### Бэкап

Достаточно скопировать файл базы. SQLite в режиме WAL, поэтому либо бери
`dsbot.db` вместе с `-wal`, либо останавливай бота перед копированием:

```bash
python main.py stop
cp /data/dsbot.db /data/dsbot.db.bak
```

## Если панель не принимает `-r requirements.txt`

Впиши пакеты напрямую, через пробел:

```
discord-py aiosqlite sqlalchemy pydantic pydantic-settings structlog typer pyyaml tzdata
```

Версии есть в `requirements.txt`, но обычно достаточно свежих.

## Отличия Linux от Windows

| | Windows | Linux (панель) |
|---|---|---|
| Остановка процесса | PowerShell + CIM | `ps` |
| Пути | `\` | `/` (в коде всё через `pathlib`) |
| Кодировка консоли | cp866, чинится принудительным UTF-8 | UTF-8 из коробки |

Файловая блокировка (`var/dsbot.lock`) реализована и через `msvcrt`, и через `fcntl`.
